# Contributing to Talent Prism

Thank you for your interest in contributing to Talent Prism.

Talent Prism is an open-source reference implementation for building AI-assisted applicant intake and evaluation platforms. Contributions that improve the architecture, documentation, workflows, security, integrations, and developer experience are greatly appreciated.

---

# Before You Contribute

Please read the following documents before submitting a contribution:

- README.md
- DISCLAIMER.md
- LICENSE

Understanding the project's scope and philosophy will help ensure that contributions align with the repository's goals.

---

# Repository Philosophy

Talent Prism is a **reference implementation**, not a commercial Applicant Tracking System (ATS) or Talent Management System (TMS).

The primary goals of this repository are to:

- Demonstrate modern system architecture
- Showcase workflow automation
- Promote modular design
- Encourage extensibility
- Share engineering knowledge with the community

When contributing, prioritize:

- Simplicity
- Maintainability
- Readability
- Extensibility
- Clear documentation

---

Contributions are welcome in many forms, including:

## Documentation

- Add examples
- Clarify existing explanations

- Improve workflow organization

---

# What We're Not Looking For

Talent Prism intentionally focuses on the applicant evaluation pipeline.

Please avoid submitting features related to:

- Applicant Tracking Systems (ATS)
- CRM functionality
- Payroll
- HR management
- Billing
- Interview scheduling
- Email marketing
- Team management
- Multi-tenant SaaS administration

These are outside the scope of this repository.

---

# Coding Guidelines

Please follow these principles when contributing:

- Keep code modular.
- Prefer clear, readable implementations.
- Document non-obvious decisions.
- Avoid unnecessary complexity.
- Maintain compatibility with existing architecture whenever possible.

---

# Documentation Guidelines

Documentation should explain:

- Why something exists
- How it works
- When it should be used
- How it can be extended

Avoid documenting features that are not implemented.

---

# Pull Requests

When submitting a pull request:

- Clearly describe the problem being solved.
- Explain your proposed solution.
- Keep pull requests focused on a single topic whenever possible.
- Update documentation when necessary.
- Test your changes before submission.

Small, focused pull requests are easier to review and merge.

---

# Issues

If you discover a bug or have a feature suggestion, please open an issue before starting significant work.

When reporting issues, include:

- A clear description
- Steps to reproduce (if applicable)
- Expected behavior
- Actual behavior
- Relevant logs or screenshots

---

# Security Issues

Please do not publicly disclose security vulnerabilities.

If you believe you have discovered a security issue, please contact the maintainers privately so the issue can be investigated before public disclosure.

---

# Code of Conduct

By participating in this project, you agree to interact respectfully and constructively with other contributors.

We value:

- Respectful communication
- Constructive feedback
- Inclusive collaboration
- Professional conduct

Harassment, discrimination, or abusive behavior will not be tolerated.
